# iFolo 官网首页 · 交互方案

四版首页设计稿 + 一页面板头部探索，都基于产品的**真实界面**（v0.1.0，本机实测）。面板部分不是截图，是用 iFolo 自己的设计令牌复刻的可交互组件，所以任意缩放都清晰，也能真的点。

## 怎么打开

```sh
cd website
python3 -m http.server 8000
# 打开 http://localhost:8000
```

必须走本地服务器。直接双击 `index.html` 也能打开，但 `file://` 协议下 ES module 会被 CORS 拦掉，面板不会渲染 —— 这是 WKWebView 与 Chrome 共有的限制，产品本体也踩过同一个坑。

## 四版方案

| 文件 | 方案 | 交互概念 | 适合 |
|---|---|---|---|
| `v4-desktop.html` | **桌面模拟版**（基于方案一） | 首屏中央一台模拟的 macOS 屏幕，含动态壁纸、菜单栏、Dock；页面主体是扁平画布 | **直接上线**、接文案与下载链接 |
| `v1-edge.html` | 边缘触发式 | 首页就是产品本身：面板藏在屏幕右边缘，指针碰上去按真机的 320ms 曲线滑出 | 冷启动、建立认知 |
| `v2-scroll.html` | 滚动叙事式 | 把产品当实物展示：3D 透视扶正 + 放大裁切界面细节 | 讲清差异化、说服 |
| `v3-live.html` | 可交互演示式 | 不用下载先点一遍：编号注释高亮 + 真实键盘输入 | 落地页、转化 |
| `v5-headers.html` | 面板头部 · 减行 | 拆解现状（5 行 / 172px）并给出六种「固定头部内做减法」的方案 | 面板改版 |
| `v6-radical.html` | 编辑页头部 · 大重构 | 换掉「固定头部」这个前提，六种范式级方案（0px 常驻） | 面板改版 |
| `v7-list.html` | 列表页头部 · 重做 | 列表页头部只有 2 行 76px，问题不是高度而是重复与结构；六种方案 | 面板改版 |
| `index.html` | — | 方案索引、选型建议、文件清单（含缩放 iframe 实时预览） | 内部评审 |

### 方案 04 相对方案 01 改了什么

用户对方案一的反馈是「背景颜色有极浓的 AI 气息」。原背景是三色（蓝 + 橙 + 绿）径向光晕的 mesh 渐变——这正是 AI 生成图的典型特征。方案 04 的处理：

1. **背景去 AI 味**。页面主体回到产品报告 `docs/product-analysis.html` 那套扁平画布（`#F5F7FA` + 白卡片 + `--ink` 系中性色）。彩色只保留在首屏那台屏幕的壁纸里，且壁纸是**单一场景**（天空渐变 + 一个日/月光晕 + 三层远近山），色相成组、有明暗层次，不跨色系。
2. **首屏中央加模拟 macOS 桌面**。菜单栏、Dock、桌面窗口按真机比例做，壁纸**随真实时间**在黎明 / 白天 / 黄昏 / 夜晚之间自动切换（macOS 的 Dynamic Desktop 就是这么做的），也可在导航的「墙纸」里手动选。产品交互（面板呼出、点笔记、⌘K）就发生在这块屏幕里。
   - 注意：**只在这块屏幕里模拟 macOS**，网站自己的导航与版式不变。
3. **暗色模式**。整站 + 面板 + 屏幕壁纸联动，跟随系统（`prefers-color-scheme`）或手动切换。
4. **H5**。窄屏下屏幕改竖版（4:5）、面板占满屏宽、Dock 与边缘热区隐藏；分镜章节的面板回到文档流；提示语从「移动指针」换成触屏可读的说明。

## 面板头部探索（v5-headers.html）

编辑器模式下头部是 **5 行堆叠、172px**，占面板高度 19%：

| 行 | 内容 | 高度 |
|---|---|---|
| 顶栏 | logo + 搜索图标 + ⋯ | 36px |
| 文档内查找 | 在当前文档中查找… | 40px |
| 标签页条 | 4 个标签 + ＋ | 32px |
| 富文本工具栏 | 正文▾ B I U S </> 颜色 高亮 Emoji ⋯ | 36px |
| 面包屑 | 全部笔记 › 然后根据fi… · 已自动保存 | 28px |

六种替代方案的取舍：

| 方案 | 头部高度 | 做法 | 代价 |
|---|---|---|---|
| ① 单行制 | 68px | 顶栏/面包屑/搜索合成一行；工具栏改为选中即浮出 | 工具栏要选中才出现 |
| ② 标签即导航 | 72px | 标签条升为唯一顶行，面包屑取消 | 标签多了要溢出菜单 |
| ③ 折叠头部 | 162 → 30px | 不动结构，滚动时收成迷你条 | 顶部依然高 |
| ④ 双态互斥 | 72px | 工具栏与标签页共用一行，两段式开关切换 | 多一次切换动作 |
| ⑤ 侧栏标签 | 70px | 标签移到左侧 28px 竖栏 | 要改面板根结构；首字会重名 |
| ⑥ 无头头部 | 0px | 写作时头部全隐，指针到顶部才浮出 | 可发现性差，需键盘入口兜底 |

**推荐组合**：② 标签即导航 + ⑥ 的无头机制。② 消掉了重复信息（面包屑与标签在说同一件事），
⑥ 让写作时屏幕上只剩文字。两者叠加后，写作态 0px、切换态 72px。

## 面板头部 · 大重构（v6-radical.html）

上一页的六个方案都还在同一个前提里：**头部是一个固定横条，里面放 N 行**。
这一页换前提——头部可以不占高度、可以不常驻、可以不成条、可以不在顶部。

| 范式 | 常驻高度 | 头部变成了什么 | 代价 |
|---|---|---|---|
| ① 命令行式 | **0px** | 一个输入行（`/h2` = 转为标题 2） | 要记命令词，鼠标用户不友好 |
| ② 浮岛式 | **0px** | 一颗 168×30 的胶囊，悬停长成完整头部 | 展开时遮住首行；触屏要改点击 |
| ③ 径向菜单 | **0px** | 光标处一圈八扇区，按住 ⌥ 唤出 | 要学一次；扇区上限 8 个 |
| ④ 状态机单行 | 40px | 一行，五种面孔（空闲/输入/查找/多标签/选中） | 同位置多义，需要过渡动效 |
| ⑤ 侧栏优先 | 30px | 左侧一栏（46px 图标，悬停展开到 178px） | 占横向宽度；格式工具位置反直觉 |
| ⑥ 文档即界面 | **0px** | 正文的一部分（标题即 H1，标签变卡片横滑条） | 标题与 H1 语义合并；卡片占一行 |

每个原型都默认展开到「最有信息量」的样子，下方有按钮可以切到收起态。

**这六个里我最看好两个**：
- **③ 径向菜单** —— 它是唯一一个让「选择格式」比现在**更快**的方案。八选一只需一次方向动作，
  形成肌肉记忆后完全不用看。代价是要学一次，但一次学习的收益是长期的。
- **④ 状态机单行** —— 它是**工程成本最低**的大重构。承认「五行本来就不会同时用」，
  于是只保留一行，让它随状态变形。结构最简单，只有一行要维护。

## 列表页（首页）头部 · 六种方案（v7-list.html）

面板其实有**两个头部**，问题完全不同：

- **编辑页** 5 行 / 172px —— 问题是「太高」
- **列表页** 2 行 / 76px —— 问题是「搜索被重复了两次、标题是死的、列表没有结构」

所以列表页不能用「减行」的思路。六种方案分别回答：搜索该不该常驻、列表该不该分组、chrome 该放哪儿。

| 方案 | 头部高度 | 搜索放在哪 | 最大的好处 | 代价 |
|---|---|---|---|---|
| ① 搜索即头部 | 46px | **就是头部本身** | 同一功能只出现一次，搜索零距离 | 标题消失，位置感变弱 |
| ② 单行 + 时间分组 | **40px** | 顶栏图标，⌘F 原地展开 | 列表第一次有了结构，组头吸顶 | 分组规则要定清楚 |
| ③ 抽屉筛选 | 40px | 顶栏图标 | 把常驻的搜索行换成按需的筛选行 | 展开挤列表 |
| ④ 侧栏优先 | 32px | 内容区顶栏图标 | 置顶/标签/回收站这些缺失入口一次给全 | 占 152px 宽度 |
| ⑤ 浮岛列表 | **0px** | 浮岛展开后的第二行 | 列表从第一像素开始 | 展开遮前两条；触屏需改点击 |
| ⑥ 时间轴 | **0px** | ⌘F 全屏搜索层 | 页面上没有 chrome，时间成为可见纵轴 | 左缩进压窄行宽 |

**推荐 ② + ④ 组合**：② 用最小改动（压到一行 + 加时间分组）解决「列表没结构」这个最大的问题，
性价比最高；④ 的侧栏补齐了置顶 / 标签 / 回收站这些**当前完全没有入口**的功能，
但占宽度，建议做成可收起的（默认 46px 图标栏，悬停展开）。

一条必须遵守的既有原则：**筛选不要做成模式切换器**。
产品侧明确过「凡是要求用户先做一次选择、再找内容的控件，都应该下沉为内容上的被动标识」，
所以这里的筛选一律走抽屉或菜单，不做分段控件。

> 方案 04 没有引用 `site.css` —— 它自带完整样式，也不再用 `.ambient` 那套三色光晕背景。

### 面板组件用法

```js
import { createPanel, LOGO } from './assets/panel.js'

const panel = createPanel({
  initial: 'list',   // 'list' | 'editor' | 'search'
  height: 470,       // 正文区高度（不含顶栏/标签条/工具栏/状态栏）
  tabs: true,        // 是否显示标签页条（仅编辑器视图可见）
  toolbar: true,     // 是否显示富文本工具栏（同上）
  interactive: true, // 是否响应点击与 ⌘K / ⌘L / ⌘F / Esc
})
document.body.append(panel)

panel.__show('editor')     // 切换视图
panel.__toggleCmd(true)    // 开 / 关命令面板
```

暗色模式：面板只用语义令牌（`--accent` / `--good-soft` / `--surface` …），
不用原始色阶（`--blue-50` 这类在暗色下不会翻转）。面板自身的少数专用色收在
`.ifp` 作用域的 `--ifp-*` 里，随 `[data-theme]` 切换。

## 实现时踩到的坑

**1. 面板高度要算上"外壳"。** 正文高度之外还有顶栏 36 + 标签条 30 + 工具栏 34 + 状态栏 26 ≈ 126px。只按正文算高度，面板会溢出容器。

**2. 放大裁切的偏移公式。** `transform: scale(s) translate(tx, ty)` 在 `transform-origin: 0 0` 下，**translate 用的是元素自身坐标系**（先平移后缩放）。所以可见区域从元素坐标 `(-tx, -ty)` 开始，宽 `w/s`、高 `h/s`。想裁面板的 `(X, Y)` 处，就写 `tx: -X, ty: -Y`。这个搞反过一次，裁出来全是错位。

**3. 视图切换会改变外壳高度。** 列表 / 搜索模式下标签条与工具栏是 `display: none`，正文从 `y=36` 开始；编辑器模式下两者都显示，正文从 `y=100` 开始。裁切参数必须按目标视图分别算。

**4. sticky 的活动空间来自最近的滚动容器祖先。** 高度要给 `.story > .wrap` 而不是 `.story`；只给 section 设 `min-height` 时 `.wrap` 仍只有 100vh，卡片会直接滚走。

**5. 全页只用一个面板实例。** 两个固定/滚动面板同时存在会重叠打架。

**6. 首屏元素的实际高度要用 DOM 量，不要靠估。** 屏幕容器（`aspect-ratio: 16/10`）+ 面板 + Dock 的总高很容易超出视口。改完用 `getBoundingClientRect()` 逐个核对再截图。

**7. 绝对定位元素是兄弟节点时，后代选择器选不中。** v5 的浮出工具条 `.float-bar` 与 `.hd--s1` 是兄弟，
写 `.hd--s1 .float-bar` 永远不匹配 —— 表现为「工具栏竖排了」（因为没有 `display: flex`，
里面的 `display: flex` 子元素各自成块）。改成 `.ifp--stage .float-bar` 才对。

**8. 浮层背景必须实底。** v5 的无头头部一开始用 `linear-gradient(180deg, surface 62%, transparent)` 做背景，
结果正下方的内容从渐变的下半段透上来，两行字叠在一起。正确做法是头部用**实底**，
淡出效果放在头部**下方**（用 `::after` 撑 16px 的渐变条）。

**9. CSS 变量没定义会让整条 `conic-gradient` 静默失效。** v6 的径向菜单用
`conic-gradient(from -112.5deg, var(--sector) 0deg 43.5deg, ...)` 画 8 个扇区，
但 `--sector` 忘了定义 —— 结果是**整个环完全不显示**，而 8 个图标条目照常渲染，
看起来像「环被设计成透明的」。这类失败的排查方法：在 devtools 里看 `backgroundImage` 是否为 `none`。

**10. 原型面板的正文区必须显式给高度。** v7 的六个原型一开始都没写 `height`，
面板就被 11 条笔记的内容撑到 750px 高，内部根本滚不动 —— ⑥ 时间轴的吸顶条因此永远不出现。
给 `.ifp__body` 加上 `style="height:430px"` 之后才正常。**凡是「内部滚动」类的交互，
都要先确认滚动容器有确定的高度**，不能靠内容撑。

**11. 径向菜单的角度约定要一次定清楚。** `rotate(a) translate(r) rotate(-a)` 把元素放到角度 a 的位置；
conic-gradient 的 `from` 决定扇区起点。两者必须对齐到同一个「零度」——
我统一用「第一个扇区以正上方（-90°）为中心」，即 conic 从 `-112.5deg` 起。搞错的话
图标和扇区会错开半格，看着像设计问题而不是代码问题。

## 无头浏览器截图注意事项

`--headless --screenshot` 的虚拟时钟**不推进 CSS 过渡与动画**，截出来会停在过渡起点。这个坑在方案 04 上尤其隐蔽：

- 页面加载时 JS 会把 `data-wall` 从 `day` 改成 `night`（按时间），同时菜单栏有 `transition: background 320ms`。
- 过渡被冻结 → 自定义属性 `--mb-bg` 已经是暗值，但 `background` 的**计算值仍是亮值**。
- 表现是「菜单栏没跟着变暗」，看起来像 CSS 写错了，其实是截图假象。

正确做法是**先禁过渡、再改属性**：

```js
const s = d.createElement('style')
s.textContent = '*,*::before,*::after{transition:none!important;animation:none!important}'
  + '.reveal{opacity:1!important;transform:none!important}'
d.head.appendChild(s)
d.body.dataset.wallLum = 'x'      // 先抖一下强制重算
void d.body.offsetHeight
d.body.dataset.wallLum = 'dark'   // 此时不会触发过渡，直接落到终值
```

另外 macOS 上无头 Chrome 有**最小窗口宽度 500px**，按更窄尺寸截图会静默裁掉右侧内容。
